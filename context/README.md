# 📚 Контекстная база знаний и документация проекта Kiwi-SPI (Kiwi TCMS)

Данная директория (`context/`) предназначена для хранения актуального контекста проекта, архитектурных описаний, текущего состояния, логов выполненной работы и планов дальнейшего развития.

---

## 🗂 Структура документов

| Файл | Описание |
| :--- | :--- |
| [01_PROJECT_OVERVIEW.md](01_PROJECT_OVERVIEW.md) | **Обзор проекта**: назначение, ключевые сущности предметной области, функциональные возможности, используемый стек технологий. |
| [02_ARCHITECTURE_AND_COMPONENTS.md](02_ARCHITECTURE_AND_COMPONENTS.md) | **Архитектура и компоненты**: структура Django-приложений (`tcms.*`), модели данных, API (JSON-RPC/XML-RPC), интеграции с баг-трекерами, фронтенд и плагины. |
| [03_DEVELOPMENT_AND_OPERATIONS.md](03_DEVELOPMENT_AND_OPERATIONS.md) | **Разработка и эксплуатация**: запуск окружения, Docker/Compose, управление БД и миграциями, линтеры (`kiwi_lint`), тесты (unit, integration, load, e2e) и CI/CD. |
| [04_CURRENT_STATE.md](04_CURRENT_STATE.md) | **Текущее состояние проекта**: текущая версия (v16.4), статус зависимостей, последние изменения, примененные патчи безопасности. |
| [05_WORKLOG_AND_HISTORY.md](05_WORKLOG_AND_HISTORY.md) | **История и журнал изменений**: ключевые вехи развития (от Nitrate до Kiwi TCMS v16.4), журнал недавних коммитов и изменений. |
| [06_ROADMAP_AND_PLANS.md](06_ROADMAP_AND_PLANS.md) | **Планы и дорожная карта**: запланированные доработки, задачи по кастомизации Kiwi-SPI, интеграционные цели и бэклог. |

## 🔄 Правила поддержания актуальности контекста

1. **При добавлении нового функционала или изменении моделей**:
   - Обновлять [02_ARCHITECTURE_AND_COMPONENTS.md](02_ARCHITECTURE_AND_COMPONENTS.md) (структура моделей, API, сигналы).
   - Фиксировать изменения в [05_WORKLOG_AND_HISTORY.md](05_WORKLOG_AND_HISTORY.md) и [04_CURRENT_STATE.md](04_CURRENT_STATE.md).
2. **При обновлении стека зависимостей, миграций или конфигов**:
   - Актуализировать [04_CURRENT_STATE.md](04_CURRENT_STATE.md) и [03_DEVELOPMENT_AND_OPERATIONS.md](03_DEVELOPMENT_AND_OPERATIONS.md).
3. **При формулировании новых требований / задач от пользователя**:
   - Добавлять задачи в [06_ROADMAP_AND_PLANS.md](06_ROADMAP_AND_PLANS.md) с указанием приоритета и статуса.
