# Работа тестировщика с кейсами: повторная сверка с TestRail

Дата: 11 октября 2026 года. Ветка: `feature/testrail-workflow`.
Сравнение выполнено по официальной документации TestRail и исходникам Kiwi-SPI.

## Добавлено в этом изменении

| Сценарий | Реализация в Kiwi |
| --- | --- |
| Секции и подсекции | В каждой секции есть «Добавить подсекцию». Можно создавать несколько уровней вложенности без ухода со страницы. |
| Переименование | Кнопка с карандашом меняет название секции, сохраняя содержимое и связи. |
| Ручной порядок кейсов | Перетаскивание за значок слева немедленно сохраняет порядок. При фокусе на значке доступны ↑/↓. После обновления страницы порядок сохраняется. |
| Перенос между секциями | Перетащите кейс в раскрытую секцию того же дерева. Его ID, исполнения и результаты сохраняются. |
| Массовое перемещение и копирование | Отметьте кейсы флажками → «Переместить / скопировать выбранные кейсы» → секция и действие. Перемещение уже связанного с целью кейса не создаёт дубликат. |
| Быстрая навигация | Развернуть/свернуть все секции; ссылка на шаги и пользовательские поля в меню кейса. |
| Поиск по дереву | Видны родительские секции найденных кейсов; счётчик считает строки, включая кейс, связанный с несколькими секциями. |
| Независимое раскрытие строк | Один кейс в нескольких секциях можно раскрывать независимо; блоки вложений не конфликтуют. |
| Прогоны по дереву | Прогоны по конфигурациям и стандартный прогон без явно выбранного подмножества включают подтверждённые кейсы всех подсекций. Повторно связанный кейс включается один раз. |

Секции используют существующие дочерние `TestPlan`: новый тип сущности и миграция
не требуются. Подсекция наследует продукт, версию и тип плана, автор — создавший
её пользователь. Глубина дерева не ограничивается четырьмя уровнями; после
четвёртого уровня визуальный отступ остаётся одинаковым.

Перетаскивание доступно при сортировке по **Ключам сортировки**, по возрастанию,
без поискового фильтра. Кнопка **Ручной порядок кейсов** включает эти условия.
Это исключает сохранение порядка неполного отфильтрованного списка.

Сервер проверяет права, принадлежность текущему дереву и продукту. Изменение
порядка и массовая операция выполняются одной транзакцией. При устаревшем
порядке сервер возвращает конфликт, интерфейс восстанавливает строки и предлагает
обновить страницу. Новый порядок не может потерять кейс или создать дубликат.
Существующие исполнения не переносятся в другой запуск.

Копия — **новый независимый черновик**: текст, встроенные поля, теги, компоненты,
свойства, структурированные шаги и пользовательские поля копируются. Ссылка на
общий набор шагов остаётся общей. Результаты, история, комментарии и вложения
исходного кейса не дублируются. Это ограничение явно отличается от описанного
в TestRail копирования с историей. Для повторного тестирования используйте тот
же кейс в новом запуске.

## Что уже было доступно

- Статусы, приоритеты, автор, reviewer, назначение тестировщика, автоматизация,
  теги, компоненты, комментарии, вложения, поиск, клонирование и история Kiwi.
- Массовая смена статуса, приоритета, reviewer и тестировщика в списке плана.
- Структурированные и общие шаги, поля разных типов, снимок кейса в исполнении,
  пошаговые результаты и история попыток из предыдущего этапа.
- Этапы, циклы, запуски по окружениям, задачи тестировщика и отчёты/CSV.

## Оставшиеся пробелы для ежедневной работы с кейсами

Это список дальнейших изменений, а не заявление о полной совместимости.

| Приоритет | Возможность | Текущее ограничение / следующий шаг |
| --- | --- | --- |
| Высокий | Импорт TestRail CSV/XML | Нужен мастер сопоставления полей/шагов/секций, предварительный просмотр и отчёт об ошибках строк. |
| Высокий | Версии и восстановление | История Kiwi доступна, но нет общего diff/restore текста, структурированных шагов и пользовательских полей. |
| Высокий | Сохранённые представления | Нет сохранения набора колонок, фильтров и сортировки списка. Фильтры по новым custom fields отсутствуют. |
| Высокий | Массовое редактирование полей | Встроенные массовые операции есть; custom fields пока редактируются в карточке каждого кейса. |
| Высокий | Повтор выбранных неуспешных тестов | Есть клонирование запуска; нужен rerun подмножества по статусам с сохранением назначений и окружений. |
| Средний | Управление целыми секциями | Создание/переименование есть. Перетаскивание, массовое копирование дерева и перенос секции между родителями пока отсутствуют. |
| Средний | Выделение нескольких кейсов и drag/drop | Новый drag/drop работает с одним кейсом. Для нескольких используется добавленный диалог перемещения/копирования. |
| Средний | Корзина и восстановление | Нет отдельной корзины кейсов с периодом хранения. Удаление Kiwi не заменяется без проекта миграции и восстановления связей. |
| Средний | Шаблоны и данные | Нет выбора полноценных шаблонов Text/Steps/BDD и подстановки datasets в шаги с фиксацией в исполнении. |
| Средний | Требования и покрытие | Ссылки в шагах и дефекты доступны; нужны связи с требованиями и отчёт о покрытии/непокрытых требованиях. |
| Средний | Согласование | Статусы и reviewer есть; строгий workflow согласования версий кейсов пока не реализован. |
| Средний | Полная копия и перенос между проектами | Новый диалог ограничен одним деревом одного продукта; перенос с сопоставлением полей и политикой вложений требует отдельной реализации. |

Следующий практический этап: импорт, сохранённые представления и массовое
редактирование пользовательских полей. Они сокращают ручную работу при ведении
большой базы кейсов. Затем — diff/restore и rerun по статусам.

## Проверка

Автотесты: `tcms.testplans.tests.test_organization` проверяет сохранение порядка,
вложенность, права, атомарность, устаревшие запросы, CSRF и сохранность исполнений.
Регрессионная проверка включает прежние workflow, локализацию, кейсы, планы,
запуски и соответствующие RPC.

Результаты:

- Широкая регрессия: **651 тест, OK, 1 пропуск** (группа проверки неприменённых
  миграций отключена настройкой проекта). Включены `tcms.workflow.tests`,
  `testcases`, `testplans`, `testruns`, `core`, `management`, `kiwi_auth`, `bugs`,
  проверка назначения прав и RPC для кейсов, планов, запусков и исполнений.
- После изменения сбора кейсов для прогонов: **143 теста, OK** — все 32 новых
  теста организации кейсов плюс workflow и запуски. Эти проверки частично
  повторяют широкую регрессию; числа не складываются в число уникальных тестов.
- ESLint для `get.js` и `organization.js`, production-сборка Webpack,
  компиляция русских каталогов и `manage.py check` — успешно.
- Браузер, отдельный контейнер на `127.0.0.1:8001` с временной SQLite:
  создание второго уровня, переименование, drag/drop и сохранение после reload,
  перенос в пустую подсекцию, копирование двух кейсов, независимое раскрытие
  одинакового кейса, поиск с родителями, сворачивание дерева, ↑/↓ и конфликт
  двух вкладок — успешно. Итоговый образ проверен повторно.
- Прежняя ошибка `ReferenceError: grappelli is not defined` из библиотеки
  админ-интерфейса остаётся в консоли стандартных страниц Kiwi. Проверенным
  операциям она не мешает; изменений этой библиотеки здесь нет.

Снимок: `artifacts/case-organization.png`. Тестовые контейнеры не используют
MariaDB локального приложения. После проверки одноразовый браузерный стенд
удаляется. Рабочий проект вне этой папки не изменялся.

Повторить новые тесты:

```powershell
docker compose -f compose.test.yaml run --rm --user root tests python manage.py test tcms.testplans.tests.test_organization tcms.workflow.tests tcms.testruns.tests --noinput --settings=local.test_settings
```
