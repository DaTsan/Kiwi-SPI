# Планирование и пошаговое выполнение

Новый раздел: http://127.0.0.1:8000/workflow/ — меню **ПЛАНИРОВАНИЕ**.
Интерфейс переведён на русский. Выбор языка: значок глобуса → «Язык интерфейса» → «Русский» → «Применить». Выбор сохраняется в браузере.

## Секции и порядок кейсов

На странице тест-плана в заголовке каждой секции нажмите **Добавить подсекцию**.
Внутри неё можно создать следующую подсекцию. Карандаш переименовывает секцию.
Кнопка **Добавить тест-кейс** добавляет новый или связывает существующий кейс
именно с выбранной секцией.

Подсекции одного родителя можно переставлять за значок ≡ слева в заголовке:
перетащите его на верхнюю или нижнюю половину заголовка соседней подсекции.
При фокусе на значке работают клавиши ↑/↓. Вложенные разделы и их кейсы
перемещаются вместе с подсекцией. Порядок сохраняется сразу и учитывается
в дереве плана и новых прогонах. Новая подсекция добавляется в конец.
Для сортировки нужны права редактирования родителя и всех его подсекций;
во время поиска перетаскивание отключено. Между разными родителями подсекции
этим действием не переносятся.

Для изменения порядка потяните кейс за значок слева и отпустите выше/ниже.
Порядок сохраняется сразу; сообщение под панелью подтверждает сохранение.
Можно перетащить кейс в другую раскрытую секцию этого дерева. При фокусе на
значке клавиши ↑/↓ меняют положение в текущей секции.

Перетаскивание включено при сортировке по **Ключам сортировки**, по возрастанию,
без поиска. Кнопка со стрелками **Ручной порядок кейсов** сбрасывает поиск и
включает эту сортировку. При конфликте с изменениями в другой вкладке обновите
страницу и повторите действие.

Для нескольких кейсов: флажки → **Переместить / скопировать выбранные кейсы** →
целевая секция и действие. Перемещение сохраняет ID и результаты. Копирование
создаёт отдельные черновики с текстом, шагами, полями, свойствами, тегами и
компонентами; история, результаты, комментарии и вложения не копируются.
Для повторного выполнения создавайте новый запуск с теми же кейсами.
Свёрнутые и скрытые поиском строки не входят в выбранную группу операции.

**Развернуть все секции** и **Свернуть все секции** управляют всем деревом.
В меню строки кейса доступен переход к шагам и пользовательским полям.
Повторная сверка возможностей: `CASE-WORKFLOW-REVIEW.md`.

Прогон по конфигурациям собирает подтверждённые кейсы всего дерева плана.
Стандартный прогон без явно выбранных кейсов также включает подсекции.
Один кейс, связанный с несколькими секциями, включается один раз. Если нет
прав на подсекцию, создание прогона прерывается, чтобы не пропустить её незаметно.

## Первый цикл тестирования

1. В стандартном Kiwi создайте продукт, версию, сборку и тест-план. Добавьте
   кейсы в план и переведите готовые кейсы в подтвержденный статус.
2. Откройте кейс → **Шаги и пользовательские поля**. Нажмите
   **Добавить шаг / общий набор**, заполните «Действие» и «Ожидаемый результат», сохраните.
   Стрелки меняют порядок, «Удалить» удаляет шаг после сохранения.
3. В ПЛАНИРОВАНИЕ → **Планирование** выберите продукт, создайте **Новый этап**
   со сроками, затем **Новый цикл** с этим этапом.
4. Откройте цикл → **Создать прогоны по конфигурациям**. Выберите план и активную
   сборку именно его версии. Можно выбрать несколько окружений, созданных
   через меню администрирования: для каждого появится отдельный запуск. Без окружения
   создается один запуск. В него входят подтвержденные кейсы выбранного плана.
5. Откройте запуск → исполнение кейса. Укажите статусы шагов и фактические результаты,
   общий статус, комментарий, затраченное время в секундах и ссылки на дефекты.
   **Сохранить результат** добавляет попытку. Успешный общий результат требует
   успешных статусов всех шагов.
6. Повторное сохранение создает следующую попытку. В **История результатов**
   остаются предыдущие результаты, авторы, время и детали шагов.
7. **Мои задачи** показывает назначенные вам незавершенные и отрицательные
   исполнения открытых запусков. **Прогресс и отчёты** показывает прогресс
   и позволяет скачать CSV. В цикле и этапе есть ссылка **Отчёт / CSV**
   с соответствующим фильтром.

Существующий запуск можно привязать в цикле через **Добавить существующий прогон**
или на новой странице запуска через форму планирования. Один запуск входит
в один цикл и один этап; этап запуска должен совпадать с этапом
цикла. Закрытый запуск нужно открыть в стандартном редакторе, прежде чем
добавлять результаты.

## Общие шаги и поля

**Планирование → Библиотека общих шагов → Новый общий набор шагов** создает общий
процедурный блок продукта. В редакторе кейса выберите общий набор в отдельной
строке, оставив действие и ожидаемый результат пустыми. Изменения библиотеки отражаются в
кейсе; снимки уже созданных исполнений сохраняются.

Администратор может создать **Новое пользовательское поле** для тест-кейса или результата:
текст, целое число, флажок, список выбора, дата, URL. Ключ — постоянное техническое значение;
для списка варианты задаются по одному на строку. «Обязательное» делает поле
обязательным. Снятый флажок и число 0 являются допустимыми значениями.
Неиспользуемое поле можно деактивировать. Тип и ключ созданного поля
не меняются, чтобы не исказить сохраненные значения.

## Совместимость и ограничения первой версии

- Обычные страницы Kiwi, Markdown, комментарии, вложения, API и матрицы
  остаются доступны. Из стандартного запуска есть кнопка
  **Выполнение шагов, результаты и планирование**.
- Результаты нового режима обновляют обычный статус исполнения Kiwi.
  Изменения через прежний интерфейс/API остаются в прежней истории;
  отдельную пошаговую попытку они не создают.
- Новое исполнение получает снимок кейса, шагов и полей при создании.
  Старое исполнение получает снимок текущего определения при первом
  открытии нового режима; на странице это явно отмечено.
- При клонировании кейса в другой продукт общие блоки становятся обычными
  шагами. Переносятся только совместимые поля с одинаковыми ключами и типами;
  обязательные поля целевого продукта нужно заполнить в новом черновике.
- Связь этапа с родителем задает иерархию. Прогресс этапа учитывает
  непосредственно привязанные запуски; подчиненные этапы показываются отдельно.
- На экране отображается до 100 объектов раздела и до 1000 исполнений/строк
  отчета. CSV содержит весь результат выбранного фильтра. Полноценная пагинация
  и расширенные сохраненные представления входят в последующие этапы.
- Импорт TestRail, datasets, rerun подмножества, согласования и API новых
  сущностей пока не реализованы. Полный план — TESTRAIL-GAP-ANALYSIS.md.

## Запуск тестов

Из папки этого проекта при работающем Docker Desktop:

```powershell
docker compose -f compose.test.yaml build tests
docker compose -f compose.test.yaml run --rm tests
```

Тесты используют временную SQLite внутри одноразового контейнера. К базе
MariaDB локального приложения они не подключаются. При изменении зависимостей
или статических ресурсов пересоберите тестовый образ перед проверкой.
