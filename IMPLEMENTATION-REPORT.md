# Отчет о сближении Kiwi-SPI с TestRail

Дата: 11 октября 2026 года. Исходная версия: `624f819c8`, Kiwi 16.4.
Изменения находятся в `C:\Users\prode\Desktop\kiwi`, ветка `feature/testrail-workflow`.
Повторная сверка работы с кейсами и новые секции описаны в `CASE-WORKFLOW-REVIEW.md`.

## Анализ и объем

Исследована публичная официальная документация TestRail: сущности, milestones,
планы и конфигурации, shared steps, custom fields, отчеты, версии и datasets.
Сравнение с исходниками, ссылки и план из 16 направлений находятся в
[TESTRAIL-GAP-ANALYSIS.md](TESTRAIL-GAP-ANALYSIS.md). Файл составлен до реализации.

В этой итерации реализована базовая версия F01–F07. Полная функциональная
идентичность TestRail не заявляется. F08–F16 остаются следующими этапами.

Добавлено приложение `tcms.workflow`, одна миграция с новыми таблицами,
раздел WORKFLOW, ссылки из dashboard, карточек кейса и запуска. Проверяются
общие и объектные права Kiwi/Guardian; экспорт и административное чтение
результатов учитывают видимость родительского запуска. POST защищены CSRF,
текст экранируется, опасные формулы CSV получают защитный префикс.

Клонирование сохраняет новые данные. При переносе в другой продукт общие
блоки раскрываются в обычные шаги; поля копируются только при совпадении
ключей и типов. Исправлена обнаруженная тестами ошибка прежнего клонирования:
служебные атрибуты истории больше не передаются конструктору TestCase.

## Совместимость и ограничения

- Обычные страницы, Markdown, комментарии, вложения, telemetry и прежний API
  продолжают использовать существующие сущности Kiwi.
- Новые попытки добавляются через новый режим. Изменения старым интерфейсом/API
  остаются в старой истории и не создают отдельную пошаговую попытку.
- Для старого исполнения снимок фиксируется при первом открытии нового режима
  из текущего определения; восстановить отсутствовавшие ранее структурированные
  шаги задним числом невозможно.
- Запрет изменения попыток и снимков действует в коде приложения и админке;
  отдельного запрета для прямого SQL или QuerySet.update нет.
- Конфигурации выбираются как готовые Environment. Независимые группы
  конфигураций TestRail, datasets, rerun подмножества, мастер импорта,
  согласования, полноценный diff/restore и новый внешний API еще не добавлены.
- Прогресс milestone считается по непосредственно связанным запускам;
  дочерние milestone перечисляются отдельно. Отчеты первой версии базовые.
- Новые страницы пока англоязычные. Экранные списки ограничены 100/1000 строками;
  CSV выгружает весь набор, соответствующий фильтрам и правам.
- В исходном коммите отсутствует модель TestCaseFieldSettings при наличии ее
  миграций 0026–0028. Предложенное Django удаление этой таблицы исключено;
  существующая таблица и данные сохраняются. Общая проверка drift всех моделей
  поэтому не может считаться чистой без отдельного исправления исходного проекта.

В большом прогоне обнаружено 398 тестов; итог unittest — 394 с одним пропуском
класса проверки непримененных миграций. Этот класс в исходном репозитории
включается переменной `TEST_DASHBOARD_CHECK_UNAPPLIED_MIGRATIONS`, которая не
задавалась. Пропущенный класс содержит несколько тестов. Ошибок и неудачных
проверок в итоговых прогонах нет. Повторные 50 тестов входят в большой набор,
это не 50 дополнительных уникальных тестов.

Новые проверки покрывают валидацию и иерархию milestones, общие шаги,
неизменность снимков, клонирование в том же и другом продукте, типы и
обязательность полей, два окружения, отклонение несовместимой сборки без
частичной записи, закрытые циклы/запуски, несколько попыток, статусы и время,
права на объекты, скрытые запуски в отчете/CSV/админке, CSRF и экранирование.

На локальной MariaDB через настоящий браузер проверены:

1. Добавление шага, две перестановки вверх, удаление несохраненной строки,
   сохранение и восстановление правильного порядка после загрузки страницы.
2. Создание двух запусков Chrome/Firefox из одного цикла.
3. Сохранение неуспешной и успешной попыток с тремя результатами шагов,
   временем, дефектом и обязательным URL-полем. Обе попытки видны в истории.
4. Прогресс: 2 теста, 1 успешный, 1 незавершенный, выполнение 50%.
5. CSV: 2 строки текущих результатов, последняя попытка в выгрузке.
6. Изменение общего блока после создания исполнений сохраняет исходный снимок.
7. После выбора продукта в отчете сохраняется фильтр цикла. Найденная при
   браузерной проверке ошибка сброса фильтра исправлена и покрыта тестом.

Временные данные обоих браузерных прогонов удалены вместе с их историей;
отсутствие объектов с уникальными QA-метками проверено. Учетная запись
администратора сохранена. Снимки тестового состояния до удаления данных:
[отчет](artifacts/workflow-report.jpg), [сохраненный фильтр](artifacts/workflow-filter.jpg).

## Локальное окружение и границы

Используются только Compose-проекты `kiwi-spi-local` и `kiwi-spi-tests`.
Автотесты работают с временной SQLite в одноразовом контейнере, без подключения
к MariaDB локального приложения. До миграции локальной базы сделана копия
`backups/before-workflow-20261011.sql` (исключена из Git и Docker-образа).
Другие проекты, контейнеры и настройки компьютера не изменялись.

Адрес нового раздела: http://127.0.0.1:8000/workflow/.
Запуск: `start-local.cmd`; остановка: `stop-local.cmd`.
Маршрут работы и воспроизведение тестов: [WORKFLOW-GUIDE.md](WORKFLOW-GUIDE.md).
